# Full code review — 2026-07-07

Repo-wide review (all ~3600 lines: bugs, security, HA/HACS best practices).
Work the unchecked items top-down; severity ordered. Update the checkboxes as
fixes land.

## 🔴 Security

- [x] **1. `dispdata_secret` leaks via diagnostics** — `diagnostics.py`
  `TO_REDACT` only covers `local_token`, but `entry.data` also contains
  `dispdata_secret` (and `mac`). Diagnostics dumps get shared on forums/
  issues; with the secret anyone reaching HA's HTTP port can read **any**
  entity state via the unauthenticated dispdata view.
  Fix: `TO_REDACT = {CONF_LOCAL_TOKEN, CONF_DISPDATA_SECRET, CONF_MAC}`.

- [x] **2. DispData view exposes every entity, not just configured ones** —
  `dispdata.py` `/dispdata/{secret}/{entity_id}` returns the state of ANY
  entity id. Restrict to an allowlist populated when poll URLs are built
  (dispdata_text sensors/items + card slots); everything else → 403.

- [x] **3. `image_asset` path traversal** — `screens.py _load_image`
  `os.path.join(img_dir, name)` with template output escapes the img/ dir
  via `../`. Admin-only config, low risk; clamp with `os.path.basename()`.

## 🟠 Bugs / robustness

- [ ] **4. Entities never become `unavailable`** — `coordinator.py`
  `_async_update_data` never raises `UpdateFailed`; device errors are stored
  as strings, so `CoordinatorEntity.available` stays True forever. Raise
  `UpdateFailed` on transport failure (mind the interaction with IP
  self-healing, which must keep running). Silver-tier requirement.

- [ ] **5. Templates rendered in executor threads** — `screens.py _tpl`,
  `render_page`, `cards.py _resolve_color` run inside
  `async_add_executor_job` but call `Template.async_render()`, an event-loop
  API. Works today; newer HA increasingly reports/blocks non-thread-safe
  calls — most likely future breakage. Structural fix: pre-render templates
  in the loop, pass results to the executor.

- [ ] **6. `show_message`/`show_image` target ALL devices** — `services.py`
  iterates every coordinator; two Times Gates both show the message. Add
  `device_id` / config-entry targeting to the service schemas.

- [ ] **7. `value_template` registry grows unbounded** — `dispdata.py`
  `register_value_template` keys by md5 and never evicts; old templates stay
  pollable and leak memory across config edits. Cap or clean per entry.

- [ ] **8. PIL work in the event loop** — `coordinator.py _build_card` does
  the GIF→JPEG preview conversion in the loop (~ms at 128px, but HA's
  blocking-call detector may flag it). Move into the existing executor job.

## 🟡 HA / HACS compliance

- [x] **9. `hacs.json` has a dead `filename` key** — `filename:
  divoom_times_gate.zip` belongs with `zip_release: true`; without it it's
  meaningless and can confuse HACS once releases are tagged. Remove (or
  adopt zip releases deliberately).

- [ ] **10. `manifest.json`** — `Pillow>=10.1.0` can fight HA's exact core
  pin (a custom component demanding a newer minimum can break an install);
  prefer tracking HA's pin or a laxer bound. Optional: add `"loggers"`.

- [ ] **11. Restore flow pushes device commands at HA start** — `select.py`
  six entities each send a command + refresh on restore; with the device
  unreachable this slows platform startup. Prefer restoring state only and
  letting the first coordinator tick apply it.

- [ ] **12. Known backlog items (reconfirmed)** — no tests; no CI (hassfest +
  HACS validation + ruff would auto-catch #5/#10); no entity translations/
  categories on the selects; no reauth flow for a changed LocalToken.
